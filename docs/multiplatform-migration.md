# Multi-Platform Migration Plan

**Status:** Not started. Sequenced into 8 phases on a single branch; Phases 1–6 are Windows-side with zero behavior change, Phases 7–8 bring macOS up.
**Related:** `CLAUDE.md` (platform-portability notes), `docs/daemon-broker-migration.md` (prior architecture move)

This is a living document. Each phase section has an **Implementation notes** block — fill it in as you go. Don't delete prior notes; future agents read them to understand why decisions were made. Update the status table at the top of each phase section when state changes.

---

## Goals

1. **Single codebase, two platforms.** Windows and macOS build from the same tree with minimal `#[cfg]` divergence. Linux is a follow-on; the design should not preclude it.
2. **Daemon becomes pure headless service.** No tray, no dialog, no GUI. Owns SQLite, control socket, supervisor children. The existing `build_headless_state` / `run_headless_daemon_with_state` test path becomes the only run path.
3. **Honest "Quit" semantics.** When the user picks Quit from the (now app-owned) tray, every Shard process exits. No survivors except by an explicit different code path (Hide, Close window).
4. **Each phase leaves the tree green.** Phases 1–6 are pure Windows-side refactors that improve the codebase regardless of whether macOS ever ships. Stop after any phase and the project is still in a better state. Each phase should be a clean commit (or small commit cluster) on the migration branch so reverting a single phase is straightforward.

## Non-goals

- Linux support in this migration. The design accommodates it (`prctl(PR_SET_PDEATHSIG)` is the natural Linux fit for the parent-watch secondary path) but no Linux-specific code or testing happens here.
- Replacing the wire framing protocol. The existing `[u32 len][u8 type][payload]` binary codec stays.
- Replacing Tauri or moving to a non-WebView renderer.
- Notarization automation. We document the manual notarization workflow; we don't build CI for it.
- A separate macOS UI / native menu bar. Defer until parity is shipping.

## Locked design decisions

These were settled in the planning phase (Claude + Codex consult). Future agents: do **not** re-litigate without strong new evidence. Add a note here if you do.

### D1. Tray ownership moves from daemon to app

The daemon becomes headless. The Tauri app owns the tray icon via Tauri v2's built-in cross-platform tray support. Quit, Show, New Window menu items become app-side commands; "Quit" issues a `QuitDaemon` RPC to the daemon.

**Rationale:** The largest single source of platform divergence (~800 LOC of winit + tray-icon + MessageBoxW + CreateToolhelp32Snapshot in `daemon.rs`) exists to host a tray. The app's existing hide-on-close behavior (`crates/shard-app/src/lib.rs:101-120`) means the app process is always alive to host the tray. Moving the tray collapses the divergence.

**Trade-off accepted:** If the user fully kills the app process, the tray disappears until next launch. The daemon and sessions survive (separate processes). On next app launch the tray reappears and reconnects.

### D2. Orphan prevention uses an inherited liveness FD, not just PID watching

When the daemon spawns a supervisor, it creates an anonymous pipe (Windows: `CreatePipe`, Unix: `pipe2`/`socketpair`). The daemon keeps the write end open for the supervisor's lifetime. The supervisor inherits the read end and runs a tokio task that calls `exit(1)` on EOF.

**Rationale:** A pure PID watcher (`WaitForSingleObject` / `kqueue EVFILT_PROC`) has an arm-time race: the daemon can die between supervisor spawn and the watcher being registered. An inherited FD has no race — read returns EOF the instant the daemon's handle closes, for any reason (clean exit, segfault, SIGKILL).

**This subsumes the original `ParentWatch` trait proposal.** PID watching becomes optional secondary verification, not the primary mechanism. The trait can be omitted from v1.

### D3. Identity check is PID + start_time + instance token

`sysinfo::Process::start_time()` returns seconds-since-epoch — too coarse for high-confidence PID-reuse defense under fast restart/test conditions. We add an `instance_token: u128` generated by the daemon at supervisor spawn, persisted in SQLite alongside `supervisor_pid`, passed to the supervisor via CLI arg.

On adoption-on-restart, the daemon's handshake with the (claimed-orphaned) supervisor includes a `ProveIdentity { token }` exchange. Mismatched token => abandon adoption, mark session stopped.

**Rationale:** PID + start_time + token is robust against PID reuse even at sub-second granularity. The token also defeats a class of accidental cross-mounting bugs (e.g., a stale supervisor.pid file from a different daemon instance).

### D4. Shutdown intent is durable

Before starting the stop ceremony, the daemon writes a `shutdown_intent` marker to SQLite. After all supervisors confirm stopped, it clears the marker, then exits. On the next daemon launch, if the marker is set, run reconciliation: any session marked `running` with no live supervisor (per liveness FD + token handshake) gets marked `stopped` with a `crashed_during_shutdown` reason.

**Rationale:** Distinguishes "daemon crashed mid-run" (sessions might be salvageable via adoption) from "daemon crashed mid-shutdown" (sessions are intentionally being torn down; finish the job). Different recovery semantics.

### D5. Trait bypasses are fixed first

Before any other work, every direct use of `tokio::net::windows::named_pipe::NamedPipeClient` / `NamedPipeServer` / `NamedPipeTransport` outside the `transport_windows.rs` impl gets refactored to go through `SessionTransport` / `PlatformTransport` typedefs. This is Phase 1 and is a pure Windows-side refactor.

**Rationale:** Without this, the macOS port will re-introduce platform types as `#[cfg]` band-aids, defeating the abstraction. The fix is cheap on Windows alone; far cheaper than untangling it during the port.

## Phase 3 — Inherited liveness FD + supervisor instance token

**Goal:** Implement D2 and D3. Each spawned supervisor inherits a pipe FD and an instance token. The supervisor self-terminates when the daemon's pipe end closes. Identity checks during adoption verify the token.

**Status:** Not started

### Files affected

- `crates/shard-supervisor/src/liveness.rs` — new; cross-platform inherited-FD reader
- `crates/shard-supervisor/src/lib.rs` — export `liveness`
- `crates/shard-cli/src/cmd/session.rs` — `serve` subcommand reads `SHARD_LIVENESS_FD` env var (or CLI arg), spawns the watch task
- `crates/shard-cli/src/cmd/daemon.rs::handle_spawn` (~line 1820) — create pipe before spawning supervisor; pass write-end-keeper to `LiveSession`; pass read end via env / CLI arg
- `crates/shard-supervisor/src/process.rs` + `process_windows.rs` — `spawn_detached` gains a variant that takes inherited handles
- `crates/shard-core/src/sessions.rs` — add `instance_token` column to sessions table (migration); plumb through `Session` struct
- `crates/shard-transport/src/control_protocol.rs` — new frames `ProveIdentity { token: u128 }`, `IdentityProven`, `IdentityRejected`
- `crates/shard-supervisor/src/event_loop.rs` — handle `ProveIdentity` in the per-session control path
- `crates/shard-cli/src/cmd/daemon.rs::adopt_orphans` (~line 3244) — perform identity handshake before adopting

### Implementation steps

1. **SQLite migration.** Add `instance_token TEXT NOT NULL DEFAULT ''` to the sessions table (UUIDv7 or u128 hex). Update `SessionStore::create`, `SessionStore::get`, etc. to round-trip the field. Existing rows get an empty token; they fail adoption identity check (correct behavior — those supervisors are from a pre-migration daemon and should not be adopted).
2. **Liveness FD module.** In `shard-supervisor/src/liveness.rs`:
   ```rust
   pub async fn watch(fd_or_handle: RawHandle) -> ! {
       // tokio::io::AsyncRead on the inherited FD/HANDLE
       // Block on read; any return (Ok(0) = EOF, Err = closed) → exit(1)
   }
   ```
   Windows: wrap the inherited `HANDLE` with `tokio::net::windows::named_pipe::NamedPipeClient` (anonymous pipes use the same primitives). Unix: `tokio::net::UnixStream::from_std(unsafe { std::os::unix::net::UnixStream::from_raw_fd(fd) })` after `socketpair`. **Decision needed during implementation:** use anonymous pipe (`CreatePipe`/`pipe2`) or `socketpair` everywhere for uniformity. Default to `socketpair` for symmetric semantics; revisit if Windows-side hits friction.
3. **Daemon-side pipe setup.** In `handle_spawn`:
   - Create pipe / socketpair before fork/exec.
   - The supervisor's read-end FD/HANDLE is marked inheritable; daemon's write-end is **not**.
   - Pass FD number via env var: `SHARD_LIVENESS_FD=N` on Unix; on Windows, pass the inheritable HANDLE value as a hex string in `SHARD_LIVENESS_HANDLE`.
   - Pass `instance_token` as env var `SHARD_INSTANCE_TOKEN` (also persist to SQLite).
   - Daemon retains its write end inside `LiveSession` so dropping the `LiveSession` (or the daemon exiting) closes the write end → EOF on supervisor's read.
4. **Supervisor-side wiring.** In `cmd/session.rs::serve`:
   - Read `SHARD_LIVENESS_FD` / `SHARD_LIVENESS_HANDLE`; if absent, log and exit (we now require it).
   - Spawn `tokio::spawn(liveness::watch(fd))`.
   - Read `SHARD_INSTANCE_TOKEN`; store in supervisor state.
5. **Identity handshake.** In `shard-transport/src/control_protocol.rs`, add three frames. The supervisor's per-session control path, on receiving `ProveIdentity { token }`, compares to its in-memory token:
   - Match → `IdentityProven`
   - Mismatch → `IdentityRejected { reason }`, close pipe.
6. **Adoption gate.** In `adopt_orphans`, before adopting a supervisor:
   - Look up the persisted `instance_token` from SQLite.
   - Connect to the supervisor's session pipe; send `ProveIdentity { token }`.
   - On `IdentityProven`, adopt. On anything else (rejected, timeout, pipe missing), mark session `stopped` and skip.
7. **Belt and braces.** Job Object stays untouched in this phase. We're proving the new mechanism works alongside the old; we delete the old in Phase 5.

### Done when

- A supervisor whose daemon is killed via Task Manager / `kill -9` exits within ~100ms (the read on the closed pipe should fail immediately).
- A supervisor whose daemon exits cleanly via `shardctl daemon stop` exits the same way.
- Restarting the daemon successfully adopts supervisors that have a valid token in SQLite.
- Restarting the daemon refuses to adopt supervisors with an empty/mismatched token (logs a warning, marks session stopped).
- New integration test: spawn daemon, spawn supervisor, kill daemon, observe supervisor exits within timeout.
- All existing tests pass on Windows.

### Rollback strategy

Each phase should be a clean commit (or small commit cluster) so `git revert` on the phase's commits leaves the branch in the previous green state. ## Glossary

- **Daemon.** The `shardctl daemon` process. Owns SQLite, control socket, supervisor children. After this migration: headless on all platforms.
- **Supervisor.** A `shardctl session serve` process. One per running session. Owns a PTY and a session-specific IPC socket.
- **Liveness FD.** An inherited file descriptor (Unix) or HANDLE (Windows) connecting the daemon to each supervisor. The daemon owns the write end; supervisor reads the other. EOF on the read end = daemon dead = supervisor exits.
- **Instance token.** A per-supervisor random value (u128 or UUIDv7) the daemon generates, persists in SQLite, and passes to the supervisor via env var. Verified on adoption-on-restart to defeat PID reuse.
- **Shutdown intent.** A durable SQLite marker the daemon writes before starting its quit ceremony and clears after finishing. Lets the next daemon launch distinguish "crashed mid-run" from "crashed mid-shutdown."
- **Adoption.** The flow where a freshly started daemon discovers orphaned supervisors (from a previous daemon instance) by reading SQLite, identifies each via the instance-token handshake, and reconnects to manage them.
- **LSUIElement.** macOS `Info.plist` key. When `true`, the app runs without a Dock icon or menu bar — only background UI like the tray.
